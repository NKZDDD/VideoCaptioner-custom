V37 多人并发隔离

使用方式：所有人关闭旧窗口后，从同一共享路径重新启动软件。

共享保存：软件、字幕模板、模型文件、剧本绑定库、工程索引、原视频旁的 ASS/SRT 与成片。
本地保存：每次启动的独立设置、缓存数据库、日志、工作文件与处理中间文件。
位置：本机 %LOCALAPPDATA%\VideoCaptioner\<软件目录标识>\sessions\<会话编号>。

新电脑首次启动自动继承共享 AppData\settings.json。
同一 Windows 用户后续启动继承最近保存的本地设置；各电脑修改设置不再覆盖共享默认值。
如果共享默认 API Key 或参数改变，已经使用过的电脑不会自动覆盖自己的配置，应在该电脑界面更新。
模型仍读取共享目录；本次不复制大模型，也不限制已有服务端额度。

每个全流程转录任务有独立工作子目录；同名但不同来源的视频不会共享中间文件。
同一个源视频或同一个目标输出正在被占用时，其他任务会明确提示忙，请稍后重试；不同任务可各自运行。
锁由系统管理，正常结束或进程退出后释放。锁目录里留下的 .lock 文件不代表任务仍在运行，不要手工删除。

共享工程、剧本索引采用短事务锁与独立临时文件原子替换。
模板和原位保存的字幕检查加载时版本，别人已经修改则拒绝覆盖，提示重新加载。
新工程镜像存放在共享 AppData\batch_projects\projects，旧工程索引继续读取。
原位修改后重新合成仍使用原视频旁的 ASS 及工程冻结样式。

注意：这次完成的是运行文件与共享写入隔离，没有部署全局 API 排队服务器。
多台电脑共用 API Key 时仍受服务商并发及额度约束。共享盘带宽仍会影响视频读取与成片写入。
旧版本进程不认识新版资源锁，混用时无法提供完整保护，所有电脑都应重启后使用新版。
